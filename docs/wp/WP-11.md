## The load-bearing decisions
1. **No new table, no new event kind.** Alarms → the existing `anomalies` table (self-clearing upsert); dunning drafts → `messages` rows; hold/surface signals → `message.received{note,internal}`; snapshots → R2; aging/statement → views. The one schema change (migration `0007`) adds two columns to the mutable `documents` table — no table spent.
2. **The QuickBooks export is journal-only + code-provably penny-exact.** `exportJournal` is balanced by construction; one canonical chart-of-accounts every surface sources (no CoA drift); the vendored month fixture reconciles AR/AP to the penny; the live QB-sandbox import is an external CONFIRM. Native GL stays forbidden.
3. **Dunning is DRAFT-ONLY + human-send.** The Collector never auto-sends (REQ-032 verbatim); a human clicks send (a lens/tenant-scoped route), idempotent, with an honest hold — the human IS the approval.
4. **The recon sweep is bounded by a self-clearing hold marker.** A permanently-held POD would otherwise re-enqueue forever; the Biller's durable terminal-hold marker excludes it from the anti-join after one write — safe, bounded re-drive.
5. **The destructive R2 retention delete is fail-safe + tenant-namespaced.** POD kept 7yr (excluded); an unknown class fails safe to KEEP; the delete is confined to `evidence/<tenant>/` with a defense-in-depth guard; delete-then-tombstone is crash-safe + idempotent + preserves row-iff-bytes.
6. **Honesty is absolute.** Every metric/journal figure is a real drillable number (integer cents) or the literal `UNKNOWN`/a NULL — never fabricated; a projection miss (credit gap) is surfaced loudly, never silently dropped or invented.

## WP-exit audit swarm (REQ-119)
A 6-lens adversarial swarm ran at exit (attack → independent refutation → synthesis), weighted to the destructive R2 delete, money-correctness (QB journal + interline splits), dunning send-on-approval, Watchtower/recon bounding, the four hardenings, and tenant-isolation/budgets/append-only. 8 raw findings; 2 survived independent verification, both MINOR. **NO OPEN CRITICALS — WP-11 is clear to close.**

**Found + CLOSED (both MINOR, both fixed this pass):**
- **A (REQ-198) — retention re-instate stamped the stale ledger time.** Re-uploading a retention-tombstoned `default` doc bound the original >1yr-old `recorded_at` as `created_ts` (contradicting its own "restart from re-submission" comment), so the next sweep tick re-deleted the freshly-restored bytes and the uploader got a false 200 — a narrow liveness bug on >1yr-old non-POD evidence (POD is sweep-excluded; no correctness/money/isolation impact). → Bind the re-submission wall-clock `now`. Proving test (RED without the fix): re-instate a >1yr-old doc → `created_ts` is recent + survives a sweep tick.
- **B (REQ-199) — recon re-drive was unbounded on an orphan POD.** A committed `pod.signed` on an un-booked stream (no `shipments` row → the Biller's `shipment_not_found` skip writes no marker) re-matched the anti-join every cron tick forever — idempotent (no double invoice) and already surfaced by the Watchtower unbilled alarm, so queue-noise, not silent or runaway. → The recon re-drive now requires a `shipments` row (only billable streams re-drive); the shared unbilled predicate is unchanged so the alarm still surfaces the orphan. Proving test (RED without the fix): an orphan POD → 0 re-enqueues but still fires the unbilled alarm; a booked POD still re-drives.

**Strong negatives (attacked hard, HELD) — the three Critical-class lenses returned clean:** MONEY-CORRECTNESS (the QB journal balances + reconciles to the penny; the interline floor compares the EXECUTING share never gross — the $222,084/35-lb regression); the FOUR HARDENINGS (REQ-180 floor airtight, REQ-183 credit-gap loud + no fabricated party, REQ-176 held-reply excluded with the REQ-174 backstop intact, REQ-178 from_name pin canonical-safe); and TENANT-ISOLATION + BUDGETS + APPEND-ONLY (no cross-tenant read, no budget breach, NO `UPDATE`/`DELETE` path on `events` anywhere in WP-11). The "fail-dangerous delete" attack (created_ts DEFAULT 0) was refuted twice (both insert paths bind `recorded_at`; row-iff-bytes holds), and "held dunning mislabeled sent" was refuted. The three lenses that would have produced Criticals were driven hard and returned clean.
