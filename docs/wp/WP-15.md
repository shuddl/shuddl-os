## What shipped — the zero-cutover overlay, purely additive
The strategy (genesis/05): SHUDDL runs ALONGSIDE the incumbent — mirror the legacy export into the ledger, run BOTH computations, prove PARITY on a shadow dashboard, flip authority PER-MODULE only behind green gates, and AUTO-FALL-BACK to legacy on drift. Ten pieces:

1. **`authority.flipped` typed payload + `authority_map` projection** (REQ-008/023) — the frozen kind #35 payload refined to `{module,from,to,reason,gate_snapshot?,drift_ref?}`; `projectAuthority` UPSERTs `authority_map` (the flip is an append-only co-signed EVENT; the map is its projection — never mutated without an event). Replay-equivalent (a pure function of the event stream).
2. **`resolveAuthority(module)` server-side seam** (REQ-030/L8) — the single fail-closed reader (`@shuddl/ledger/authority`, re-exported to api) consulted at EVERY module's authoritative-output path (rating/invoicing/settlement/dispatch/comms). A module-aware source-scan lint (`check:authority-coverage`) makes a silent authority bypass a build failure — 9 (module,file) consults across 8 files (incl. the Concierge's dual rating+comms consult and the EDI-204 rating consult).
3. **The Gatekeeper flip guard** (REQ-023/030) — `POST /v1/authority/:module/flip` (admin, co-signed by the recorded actor): a FORWARD flip is BLOCKED unless `gatesGreenFor` is fresh-green (parity `within_gate` re-derived live, NEVER the stored snapshot); a BACKWARD/fallback flip is ALWAYS allowed. Money modules (invoicing/settlement) are blocked-by-construction (no in-repo clean-close signal). `authority.flipped` is refused on the generic events route AND structurally rejected off `t:root` at the DO — no bypass.
4. **The continuous 171-col mirror adapter** (REQ-021/022/035) — a PURE config-driven mapper (reusing the WP-14 migrator's confidence + gap-row law) + a per-tenant continuous sweep that mirrors the legacy export into the ledger as `source:'legacy'` events via the api DO, watermark-diffed (O(changed)), gap-row-on-EVERY-sweep (continuous no-silent-drop), quarantine-not-drop, echo-safe.
5. **The source-aware ledger** (REQ-021/030 — the crown-jewel change) — `source:'legacy'` events are PARITY-ONLY SHADOW: the sequencer SKIPS all native projections + post-commit triggers for legacy; legacy is EXEMPT from the native physical-precondition gates (a historical mirror record, not a native assertion) while keeping every structural law; every client/partner append seam FORCES `source:'native'` (legacy producible only by the internal mirror seam); the native read-models (money_lines/status/KPIs/lens/sweeps) EXCLUDE legacy via one `NATIVE_VISIBLE_SOURCES` definition. Proven against the real `ShipmentSequencer`.
6. **The shared parity primitive** (REQ-023/152/153) — `computeModuleParity` / `computeAllParity` (`@shuddl/ledger/parity`): the SINGLE native-vs-legacy definition the flip gate, the dashboard, and the drift sweep all consume (no drift between them). UNKNOWN-honest (a missing side ⇒ `status:'UNKNOWN'`, `within_gate:false` — never a fabricated match). Tolerances = the fixture replay gates (±10% routes / ±2% aggregate).
7. **Project-back-out + the bidirectional echo soak** (REQ-022) — `projectOut` embeds the originating event id in the echo column; the soak proves the round-trip (mirror-in → project-out → re-ingest) CONVERGES with no ping-pong (an in-place correction is a bounded new event, not an oscillation). Exactly ONE `stableStringify` governs the mirror-in idSeed, the project-out, and the worker — no idSeed drift.
8. **The Command `v_parity` dashboard tile** (REQ-152/153) — the reclaimed canonical view (the OR-drill slug renamed to `v_operating_ratio`; 11/12 views, no 13th, no 4th surface): consumes `GET /v1/parity` (no client recompute), renders per-module native/legacy/drift/status UNKNOWN-honest (no fabricated green/100%/check), drills to native + legacy backing events (`includeShadow` firehose-only, never a portal/driver counterparty leak). Design CI clean (blocking).
9. **The Watchtower `parity_drift` rule + auto-fallback** (REQ-008) — a 5th self-clearing alarm; a module at `authority='native'` that DRIFTS is AUTOMATICALLY flipped back to legacy (append-only `authority.flipped{reason:'drift'}` on `t:root`). **The asymmetry (hard invariant): auto-fallback DOWN is automatic on one breach; promotion UP is NEVER automatic.** Idempotent per promotion-episode (no double-flip, no auto-re-promote); per-module fault-contained.
10. **The tenant-isolation matrix** (REQ-025) — every new read AND write path (parity read, flip write, mirror write, `includeShadow` drill, Watchtower fallback) has a non-tautological isolation case; a cross-tenant read/write is a build failure.

## Cutover seams + tech-debt (see docs/ops/GO-LIVE-CHECKLIST.md §3)
- **Defer-to-mirror suppression** — the Task-2 dormant `if (authority==='legacy')` intent-markers at the 8 consult sites: when a module is legacy-authoritative WITH a live mirror value, the compute path should present the legacy value / suppress the native customer-facing output. That is a real customer-facing CUTOVER behavior (tenant-calendar-governed), left dormant in-repo; light it up per-module at cutover.
- **Dual-control on money promotions** — the flip guard records the single deciding admin (co-sign). A second-approver (dual-control) on invoicing/settlement promotes is a candidate R4 hardening (a REQ amendment).
- **UNKNOWN-while-native liveness** — a native module whose legacy mirror goes UNKNOWN (feed stops) is unmonitored (drift is unassessable, so no auto-fallback — correct). A low-severity "mirror absent" liveness alarm is a later task.
- **DO-level legacy-seam restriction** — `source:'legacy'` is locked at the route layer (force-native) + the coverage discipline; the DO itself trusts `parsed.source`. A future append seam added without forcing native would reopen the hole. Defense-in-depth: a DO-level restriction of legacy to a verified internal marker.
- **Cursor-monotonic-on-change precondition** — continuous no-silent-drop holds only if the tenant-pack `cursorColumn` bumps on every in-place edit (a last-modified/version cursor, not creation-only). Verify at tenant-pack config review.
- **Duplicate-fallback TOCTOU** — two concurrent same-tenant Watchtower sweeps could emit a duplicate (differently-seeded) fallback event; end state still legacy (never re-promote). Unreachable on the daily sequential cron.
