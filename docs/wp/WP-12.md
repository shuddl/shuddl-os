## The no-bypass architecture (REQ-030/191)
A 204 becomes a booking ONLY through the existing gated pipeline. The Translator appends at most `quote.requested{edi}` → `quote.priced` → `agent.acted` → `approval.requested?` → `quote.accepted` (payloads byte-identical to the CSR `/v1/rate` + accept-quote path, priced through the shared `@shuddl/rater`). It **never** appends `booking.created` and never reimplements a gate — the committed `quote.accepted` triggers the **unchanged** Booking agent, which runs the credit / evidence-recipient / one-booking gate in the DO. A broker tender with no email → HELD (the gate working, not a bug).

## REQ-119 exit audit — CLEAR-TO-CLOSE
An 8-lens adversarial swarm (gate-bypass, tenant isolation, auth/injection, idempotency, hostile-X12, identity/redaction, no-price-on-air, additivity/determinism) → independent default-refute → synthesis. **Zero Critical/High.** Core safety properties verified CLEAN. Four findings surfaced and were **all fixed additively** (RED-first proving tests):
1. **F-1 (Medium) — re-tender duplicate booking/invoice** → qualified-ref shipment convergence (a re-tender sharing a load-unique ref converges onto the one stream; the per-stream one-booking guard suppresses the duplicate).
2. **A follow-on over-merge** the F-1 fix introduced (converging on an order-level PO silently dropped a distinct load) → **convergence restricted to load-unique refs (SID/BM/PRO), never PO**, with an ambiguity guard and a taxonomy-guard test. Principle: **a visible duplicate always beats a silent drop** (CLAUDE.md #10).
3. **F-3 (Low) — 990 re-allocation on redelivery** → the 990 path now mirrors the 214 sent-marker dedup.
4. **F-4 (Info) — SCAC delimiter injection** → SCAC constrained to an X12-legal charset at the parse boundary (fail-closed → quarantine).
