# WP-07 — Concierge (email-in quoting) — checklist

## DoD (genesis/08 §03)
> "Inbound freight email → parse → resolve to Party+Shipment → price → **auto-reply only when floor-clean AND confident (else queue a human)**; every communication lands on the ledger timeline; SLA timers on unanswered inbound. Acceptance demo #2: a stranger signs up and quotes in <10 min."

The DoD splits three ways — a code-provable MECHANISM (OBSERVED), a live-LLM / real-email-accuracy / real-customer-auto-send RESULT that no CI run may claim (CONFIRM-gated/PILOT), and slices that land in a later WP. WP-07 builds the email → quote loop end to end through every real seam (real parse, real Rater, real sequencer append, real send port), and proves the ONE thing that must never fail: **the machine never auto-sends a quote it can't stand behind** — below-floor/anomalous, uncorroborated, or shaky-resolution quotes queue for a human, and the money is always the Rater's over an independently re-derived request. It does NOT assert a parse-accuracy percentage or auto-send to a real customer from a test run.

## The four load-bearing decisions
1. **Message-is-truth; `messages` is a projection.** The `message.*` event is the immutable source; the `messages` row is a mutable read-model. Content projects at commit; the Concierge later UPDATEs resolution (party_id/resolved_conf/sla_due_ts) on that row. Nothing reads the projection as authority.
2. **The LLM parse is a config-gated PORT never called in CI, and NEVER gates truth.** The `DeterministicParser` is the auditable accuracy floor AND the C1 corroboration re-parser; the model only steers routing. The money is the Rater's over the deterministically-corroborated request; the sent body is a bounded template. `parse.confidence` gates nothing.
3. **Auto-send = floor-clean AND independently-corroborated AND resolution-confident — three gates, zero model trust.** A below-floor/anomalous sell holds (permanent, REQ-040); a request diverging from the deterministic re-extraction on any price-affecting field can never auto-send (REQ-171/175); a <9000 resolution queues. Any one failing → a human.
4. **A fresh quote rides a `q:` intake stream; the Concierge CREATES the shipment.** No shipment exists at inbound, so the consumer mints one with a deterministic id derived from the message event id (redelivery reproduces it), and the trigger locates the inbound by its globally-unique id, never a stream it may not know.

## Assumption log
- **The quote-stage shipment self-references all three party FKs to the requester.** A quote email rarely names the consignee/payer; consignee/bill-to firm up at BOOKING (WP-08), which must add the party-correction.
- **The party identity email is the authenticated `from_ref`.** `party_hint` (model output) is a cosmetic display-name hint only (REQ-172); the deterministic parser's hint IS `from_ref` by construction, so only a live LLM could diverge — which is exactly what REQ-172 defends.
- **The SLA window is a 4h documented default.** No per-tenant SLA-config kind exists yet; the override is a later-WP obligation. `sla_due_ts` derives from the inbound's `recorded_at`, not a fresh clock.
- **Status/claim intents route elsewhere.** WP-07's DoD is quoting; a status/claim inbound resolves `unresolved(not_quote_intent)` with no shipment stream, so it carries no SLA today (the exceptions queue is WP-11).
- **`message.sent` asserts an obligation-to-deliver, completed idempotently.** Appended before the send (the send references it by key); a retriable failure self-heals via the fast path. A PERMANENT failure leaves it recorded-but-held (REQ-176 — surfacing held replies is WP-11).
- **The interim inline `subject`/`body` (bounded 2KB/32KB) is the parse source** until the R2 body-resolver lands; `body_ref` stays the durable pointer.

## WP-exit audit swarm (REQ-119)
A 4-lens adversarial swarm ran at exit — **floor + money** (below-floor/anomaly auto-send, penny drift), **LLM + confidence** (prompt injection, model-authored ledger truth/recipient, confidence bypass), **tenant + visibility** (cross-tenant read, redaction break), and **REQ-100 + idempotency** (orphan send, duplicate/lost reply, redelivery races). Each auditor attempted to BREAK a defect class and traced the code to confirm reachability. Every Critical was fixed and re-verified. **No open Criticals at close.**

**Found + CLOSED:**
- **CRITICAL — auto-reply partial-append silently loses the reply.** `quote.requested` commits, then `quote.priced`/`message.sent` throws (a transient DO fault); redelivery finds `message.sent` absent → `already_handled` → the reply vanishes, and the auto-reply path never set an SLA so no sweep could see it. → The auto-reply path now sets `sla_due_ts` before its appends (REQ-174); a dead auto-reply is caught by the T8 overdue sweep and surfaced, not lost. Re-verified with a partial-append fault injection in `sla-sweep.test.ts`.
- **CRITICAL — an unpriceable request DLQ-loops (silent lost quote).** A parsed accessorial absent from the tenant schedule made the Rater THROW; the throw escaped into the queue's blanket retry → infinite redelivery → DLQ. → The consumer catches a pricing throw and QUEUES it (quote.requested + a human draft, `unknown_price`), REQ-173. Re-verified in `concierge.test.ts`.
- **CRITICAL (arms on the ClaudeParser CONFIRM) — model `party_hint` wrote party identity.** Resolve keyed the party off `parse.party_hint.email` (model output); a crafted email could create/match a victim's party and force the resolution confidence-bump. → Identity is pinned to the authenticated `from_ref`; `party_hint` is a cosmetic hint, bounded (REQ-172). The I2 test was extended to assert the resolved party's email equals `from_ref`.
- **MEDIUM (latent HIGH at WP-09) — corroboration failed OPEN on dims.** The model could extract dims the deterministic parser misses, flipping a would-be-UNKNOWN into an auto-send. → Dims fail closed on presence (REQ-175); price is unaffected today (dims price-inert) but the divergence-can't-send doctrine now holds.

**Registered (recorded as new scope, not left as silent gaps):** REQ-176 (held-reply surface), REQ-177 (deterministic stored request under concurrent LLM redelivery), REQ-178 (fast-path from-name pin), REQ-179 (invoice GL redaction), REQ-180 (never-widen internal floor).

**Strong negatives (attacked hard, held):** a below-floor OR anomalous quote can NEVER auto-send (the $222K anomaly net is invoked on the concierge path and ANDed into the gate); Σ `quote.priced` lines === `sell` === the reply's number, penny-exact, money always the Rater's over the corroborated request; NO cross-tenant read (db bound per allowlisted slug, DO id embeds the tenant, party/shipment/event/rate_config all single-tenant); internal notes + `call.transcribed` + `quote.priced` margins never reach the counterparty or driver lens; NO duplicate reply/quote/shipment/party under sequential, fast-path, or concurrent redelivery (deterministic ids + payload-blind DO dedupe + `INSERT OR IGNORE` + the sender key); the SLA overdue note is internal + never re-enqueues the Concierge; the model can never author the sent body/subject or the recipient.
