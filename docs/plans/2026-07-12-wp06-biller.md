# WP-06 Biller (core) Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task (this session, per the owner's choice).

**Goal:** When a POD lands, the ledger emits the invoice — same causal moment, matching the Rater to the penny — and composes the evidence email; live email/DKIM/domain wiring is a swappable, deferred tail.

**Architecture:** The Biller is agent #of-13, deterministic and LLM-free. Its **pure composition** (`composeInvoice`) lives in a new `packages/agents` package: it turns a committed `pod.signed` + the accepted `quote.priced` into an `invoice.issued` **event payload** (or a *hold* when anomalous/below-floor). The **queue consumer** (`workers/agents/src/biller.ts` — the first real agent trigger; the slot is reserved at `workers/agents/src/index.ts:39`) fires off the committed POD, appends `invoice.issued` through the existing `SHIPMENT_SEQ` DO (so the I2 invoice gate + the already-built `applyMoneyProjection` run atomically for the invoice event), then hands the composed email to a swappable **`EvidenceSender` port**. Money stays a projection of recorded events (REQ-003): the invoice lines are copied from the recorded accepted quote, never re-computed.

**Three load-bearing decisions (assumptions — stated here, not silently taken):**
1. **"Same transaction window" (doc 02:18) is realized as a synchronous, queue-triggered *second append*, not a literal single DB transaction.** The ledger appends exactly one event per DO batch (`sequencer.ts:164` — no derived-event mechanism exists), and `invoice.issued` is a distinct event with its own hash/seq. Firing the Biller off the committed `pod.signed` and appending `invoice.issued` on the same stream preserves the append-only one-event law; the I2 gate (`assertPodSigned`) enforces *no invoice without a POD that is already on the stream*. "Same second" = the REQ-031 DoD **p95 < 5s POD→email**, measured end-to-end — not one transaction. Extending the sequencer to emit a derived event atomically is the rejected alternative (it would breach the one-event-per-batch law and needs a bigger design change).
2. **Penny-parity source = the recorded accepted quote's itemized lines.** Today `QuotePricedPayload` (`contracts/src/events.ts:72`) persists only the total `sell` + floors + versions + basis, **not** the `PriceLine[]` breakdown (`rater/src/compose.ts:17`). The Biller cannot read per-line amounts off the stored quote. **T1 amends `QuotePricedPayload` to persist the itemized `lines`** so the invoice is a faithful *projection* of a recorded event (REQ-003), not a re-run that could drift if the engine changes. This is a payload change, **not** a new event kind — `EVENT_KINDS.length` stays 35.
3. **Anomaly / below-floor ⇒ HOLD, never auto-send.** REQ-031/doc 01§2: "Anomaly rules (>$/lb, >$ cap, negative) → review before send." Today the anomaly is a recorded *flag*, not a refusal. `composeInvoice` returns a `hold` (no `invoice.issued`, no email) when the accepted quote carries a non-null anomaly **or** the executing-share floor check fails. The $222,084 / 35-lb case must never auto-invoice+email (REQ-040, permanent).

**Tech Stack:** TypeScript strict (no `any`); Zod at every boundary; integer-cents money (BigInt products, never float — `rater/money.ts`, `ledger/money/split.ts`); Cloudflare Workers + the `SHIPMENT_SEQ` Durable Object; Queues (the Biller is the first consumer); R2 `EVIDENCE` (REQ-168 byte-verify); React 19 for the email render + `@shuddl/design` primitives; Vitest + `@cloudflare/vitest-pool-workers`.

**Reuse (do NOT rebuild):** `invoice.issued`/`invoice.corrected` kinds + payloads (`contracts/src/money.ts`); `money_lines`/`invoices` tables (`db/tenant/migrations/0002_domain.sql`); the pure `projectMoneyLines`/`applyMoneyProjection` projection (`ledger/src/projection/money.ts`); the I2 gate `assertPodSigned` (`ledger/src/gates/invoice-gate.ts`); the anomaly + executing-share guards (`rater/src/anomaly.ts` `detectAnomaly`, `rater/src/approval.ts` `assessApproval`/`executingShareCents`); the GL journal export (`ledger/src/gl/export.ts`); the evidence-email component (`apps/portal/src/evidence-email.tsx`); the design audit + primitives (`packages/design`).

**Budget guards (CI-enforced — must stay green):** ≤22 tables (21 used; **no new table** — invoices/money_lines/documents/anomalies all exist); 35 event kinds (**no new kind**); 5 color tokens / 2 fonts / 0 shadows on the email (design audit); REQ-024 no LLM in `packages/ledger` **and** the Biller composition is deterministic (no LLM needed anywhere in WP-06 core); tenant-isolation suite (REQ-025); traceability (every WP-06 REQ annotated at close).

**Explicitly DEFERRED to a CONFIRM-gated tail (built as a stubbed port/interface now, wired when the owner authorizes; documented in the close-out — NOT this build):** live Resend send + DKIM/SPF/DMARC (REQ-092); sending-domain warmup + >98% deliverability (REQ-157 — needs the live 2-week ramp); live SMS fallback (REQ-097 — the port method exists, the Twilio wiring is deferred); bounce/complaint→Watchtower + suppression list (REQ-157 — Watchtower is WP-11); photo/PII retention policy publish (REQ-140 — CONFIRM-2); GTM unlock (REQ-159 — M-H milestone). Per REQ-091 the per-shipment inbound address is WP-06 scope but inbound *parsing* is WP-07 (Concierge) — WP-06 only reserves the address format.
