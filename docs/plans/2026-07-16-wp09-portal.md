# WP-09 — Portal + Status Pages Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (this session). Each task is TDD: write the failing test, watch it fail, minimal code, watch it pass, commit. Security-critical tasks (T1–T5) get the two-stage review (spec then quality) PLUS an adversarial pass.

**Goal:** The Portal — the third and final surface — over the append-only ledger: a lens-scoped map home + docs/invoices + claims-with-custody-chain for an authenticated party; a **guest quote in <60s** and a **public per-shipment status page**, both no-auth; all reads lens-minimal and unforgeable under adversarial tests. Plus close the one open security Critical (C-1, the positions GPS channel) because the portal publishes that channel.

**Architecture:** Two intertwined **no-auth** surfaces mount at a dedicated **`/pub/*`** prefix (registered BEFORE `app.use("/v1/*", auth)` + `app.use("/v1/*", idempotency)`, exactly like `/v1/health`) so neither middleware ever runs on a session-less path. (1) **Public status** = a domain-separated HS256 **capability token** (`STATUS_SECRET = HMAC(JWT_SECRET,"shuddl-status-cap-v1")`) carrying `{typ,t,s,exp}` — tenant+shipment live INSIDE the MAC, so neither is client-forgeable or enumerable; the read returns a **projection-only** positive-allowlist body (never `readEvents`), geo always city-coarse (the link is forwardable). (2) **Guest quote** = a **pure preview** (`priceShipment` called directly, ZERO ledger append), tenant resolved from the CF-routed hostname via a static allowlist (never the `Host` header). The authed Portal (party session) reuses the existing party lens, gates, and Booking path unchanged. **No new Role, EventKind, table, or lens scope.**

**Tech Stack:** Cloudflare Workers + Hono · D1 per-tenant · R2 (evidence signed URLs) · `hono/jwt` (HS256, same primitive as auth) · React 19 + Vite PWA (`apps/portal`, reusing `packages/map` + `packages/design`) · TypeScript strict, no `any` · Zod `.strict()` at every boundary · integer-cents/microdegree canonical law.

## The locked hard decisions (resolve the real ambiguity up front)
- **D1 — Public status (REQ-086/187/188):** `GET /pub/status/:cap` (public, projection-only). `:cap` = HS256 token `{typ:"status-cap",t,s,exp}` verified under `STATUS_SECRET` (domain-separated from `JWT_SECRET`). Body = `.strict()` allowlist `{state, out_for_delivery, position?, eta?}` from `status_cache` + latest `positions` row; **`assigned_driver` never extracted**; position **always** `generalizePosition(p,false)` (~11km, coarse EVEN post-OFD — the link forwards). Headers `Referrer-Policy: no-referrer` + `Cache-Control: no-store`. Mint via `POST /v1/shipments/:id/status-link` (authed), which resolves `:id` through `lensWhere(lensFor(session))` so a portal party mints ONLY for its own shipments; `t` baked from `session.tenant`. **No visibility-default change; the frozen 35-pair snapshot stays byte-untouched.**
- **D2 — Guest quote (REQ-051/189):** `POST /pub/quote`, no session. Tenant from `new URL(c.req.url).hostname` (NEVER `c.req.header("Host")`) via a static `HOST_TENANTS` allowlist (structural clone of `TENANT_BINDINGS`; `values(HOST_TENANTS) ⊆ keys(TENANT_BINDINGS)`). **Preview only** — calls `priceShipment(request, config)` directly, appends NOTHING, touches no DO/stream. Guest `.strict()` schema (`origin_zip,dest_zip,weight_lb?,dims?,accessorials?`) with **NO `shipment_id`**. Response `.strict()` `{status, sell_cents, lines?, transit}` — **excludes floors/basis/versions/approval/anomaly; `assessApproval` NEVER called**. Booking stays impossible by construction.
- **D3 — Dims/density:** DEFER density/class rating (protects the 504-sweep + REQ-040 anomaly regression, CLAUDE.md rule 4). Dims stay price-inert; REQ-175's C1 fail-closed gate already shipped in WP-07 — T11 adds a regression-guard test, nothing more.
- **D4 — Docs (REQ-085):** doc-row visibility is DERIVED from the recording event's resolved visibility (fail-closed skill), never a lens bypass; a POD/placed-photo that is `counterparty`-visible makes its `documents` row `counterparty`-visible. Build the R2 signed-URL byte resolver (also unblocks the Biller's `photos:{}` gap, biller.ts:409).
- **D5 — Claims (REQ-085):** ride existing kinds (`custody.transferred`/`osd.captured`/`exception.raised` event-chain + `documents kind='claim'` + `approval.requested/decided` adjudication) — zero budget, doc-10:37 sanctioned ("no claims table"). VIEW = read the chain under the party lens. FILING = a narrow portal seam (a `message.received` on the portal channel, which already exists in `messages.channel`).
- **D6 — Invoice leak (REQ-179, PULLED FORWARD):** the portal is the FIRST counterparty surface that reads `invoice.issued`; today `redact.ts` strips top-level keys only and cannot reach `lines[].gl_map`/`division`. Build the nested redaction NOW (fail-closed) — shipping a portal that leaks margin internals to the counterparty is unacceptable. Annotate REQ-179; note in close-out it landed early.
- **D7 — Transport:** add a scoped CORS middleware for the portal/status origins; the no-auth routes live in `workers/api` (no separate worker). Tiles/CF-rate-rule are deploy items (T-deploy note, not code).
- **D8 — Views:** portal reads are projection QUERIES, not named D1 `CREATE VIEW`s (no view-budget spend; no new CI check — that would be new scope).
