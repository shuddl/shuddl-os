## Task 1: Make the anchors backfill deterministic

`POST /v1/anchors/run` returns 500 in most full-suite runs of `workers/api` and passes in isolation. This blocks `verify:dev`, `verify:merge` and therefore every certification this plan is supposed to produce. It predates this branch (the branch changes no source `workers/api` executes), and it is recorded in `docs/ops/GO-LIVE-CHECKLIST.md` under repository-owned failures.

**Root cause.** `runDailyAnchor` (`packages/ledger/src/anchor.ts:209`) anchors every unanchored day from `MIN(recorded_at)` to yesterday. Under `isolatedStorage: false` + `singleWorker: true` (`workers/api/vitest.config.ts:22-23`) the tenant D1 holds whatever every other test file wrote, so the day set depends on file order. `anchorDay` handles its OWN failure modes (the boundary race returns `"failed"`, a TSA failure calls `recordTsaFailure` then returns `"failed"`), but any OTHER exception — e.g. a malformed hash reaching `hexToBytes` inside `dayLeaves` — escapes `anchorDay`, escapes `runDailyAnchor`, and fails the whole request.

**The fix is the contract the result already declares.** `AnchorRunResult` has three arrays — `anchored`, `skipped`, `failed`. A backfill over N days must not abandon N−1 good days because one day is unreadable; that day belongs in `failed`. This is a robustness fix in the ledger package, so it gets a test that fails first and it must NOT weaken any existing guarantee: a day that fails still produces NO `documents` row and NO R2 object, exactly as today.

**Files:**
- Modify: `packages/ledger/src/anchor.ts` (the `for (const day of candidates)` loop, ~line 240)
- Test: `packages/ledger/test/anchor.test.ts` (add to the existing file)

**Step 1: Read the existing anchor tests first**

```bash

ls packages/ledger/test/ | grep -i anchor
sed -n '1,60p' packages/ledger/test/anchor.test.ts
```

Match the file's existing fixture style (how it builds a `db` stub / real D1, how it constructs `AnchorDeps`). Do not invent a new harness.

**Step 2: Write the failing test**

Add a test asserting that one unreadable day does not sink the run. Adapt the fixture helpers to the ones already in the file:

```ts
it("a day that throws goes into failed[] — it never fails the whole backfill", async () => {
  // Two anchorable days. The first is poisoned with a row the leaf reader cannot parse; the second
  // is clean. Before this fix the exception escaped runDailyAnchor and the caller 500'd, losing the
  // good day with the bad one.
  const deps = depsWithPoisonedDay(); // build via the file's existing helpers
  const res = await runDailyAnchor(deps);

  expect(res.failed).toContain(POISONED_DAY);
  expect(res.anchored).toContain(CLEAN_DAY);
  // The failed day must leave NO partial anchor behind.
  const doc = await deps.db.prepare("SELECT id FROM documents WHERE id = ?").bind(`anchor:${POISONED_DAY}`).first();
  expect(doc).toBeNull();
});
```

**Step 3: Run it and watch it fail**


Expected: FAIL — the exception propagates out of `runDailyAnchor` and the test rejects.

**Step 4: Implement**

In `runDailyAnchor`, contain each day:

```ts
  for (const day of candidates) {
    // One unreadable day must not abandon the others. anchorDay already returns "failed" for the
    // boundary race and for a TSA refusal; this catches everything else (a malformed row reaching the
    // leaf reader, an R2 fault) so the run reports it in `failed` — the array this result declares for
    // exactly this purpose — instead of 500ing the request and losing every good day with it.
    let outcome: "anchored" | "failed";
    try {
      outcome = await anchorDay(deps, day);
    } catch {
      outcome = "failed";
    }
    (outcome === "anchored" ? result.anchored : result.failed).push(day);
  }
```

Do NOT swallow the cause silently if the file already has a recording seam — if `recordTsaFailure` (or similar) is the established pattern for noting why a day failed, follow it. Read the surrounding code before choosing.
