# WP-10 — Command Surface Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Each task is TDD. Server seams (Phase A) get the two-stage review + an adversarial pass; the KPI honesty + the new write seam are the risk centers.

**Goal:** The Command surface (surface #1) over the append-only ledger: a live lens-scoped map home, the approvals/exceptions/money queues as dark panels, a ⌘K command bar that drives the real verbs, a KPI strip whose every number clicks through to its ledger events, a read-only copilot that cites-or-abstains, and the CSR net-new phone/walk-in intake that books from scratch — so a non-freight tester passes the 10-minute L6 acceptance.

**Architecture:** Command is a React PWA (`apps/command`, today a WP-03 shell) that reuses `packages/map` (the exception-pulse/world-dim demo #5 is already built), `packages/design` (Metric/CountUp/Input primitives exist), and the WP-09 portal client pattern (`lib/api.ts`/`session.ts`/`router.ts`/vitest). The real build is **server read seams** (KPI compute, queue read-models, copilot) + the **CSR intake write seam** (`POST /v1/parties` + `/v1/shipments`, then reuse `/v1/rate` → `accept-quote` → the WP-08 Booking agent) + the **client** (⌘K palette, queues, KPI strip, copilot UI, the 12-view router, the live map feed). The command bar is a DETERMINISTIC palette (no LLM); the copilot's LLM lives ONLY in `packages/agents` (REQ-024), pure over an injected read port. **Honesty law: a KPI shows a real drillable number or `UNKNOWN` — never a fabricated one.**

**Tech Stack:** Cloudflare Workers + Hono · D1 per-tenant · React 19 + Vite (`apps/command`) · `packages/map`/`packages/design` reuse · TypeScript strict, no `any` · Zod `.strict()` · integer-cents/microdegree law · LLM only in `packages/agents`.

## The locked decisions
- **D-a — Command bar = DETERMINISTIC ⌘K palette (REQ-081/024).** A fixed set of ~20 canonical commands mapping to the existing API verbs (rate/accept/schedule/dispatch/intake/navigate). NO LLM in the command app/route/ledger/rater. (If NL is ever added it is an agents-port; not v1.)
- **D-b — CSR intake = discrete `POST /v1/parties` + `POST /v1/shipments` (REQ-150/030).** Ops/admin only, lens/tenant-scoped, gate-parity (the booking still flows through `#enforceBooking`). The command-bar CSR flow orchestrates: create/find parties → create the quote-stage shipments row → `/v1/rate` → `/v1/shipments/:id/accept-quote` → the Booking agent. UI-DECOUPLED so WP-13 MCP calls the same endpoints. Party creation is SYNCHRONOUS + deterministic (no LLM — unlike the Concierge's email path).
- **D-c — Copilot = read-only, cite-or-abstain, over `readEvents` (REQ-038/024).** Pure core in `packages/agents/src/copilot/` over an INJECTED read port (no `@shuddl/ledger` import); a config-gated LLM adapter (Deterministic/NotConfigured/Claude, mirroring the Concierge parser); every claim grounded on a REAL retrieved event id (a Zod `.strict()` `AnswerResult {text, citations: EventRef[], abstained}`); malformed/ungrounded model output → ABSTAIN (never a fabricated fact); the model's self-reported confidence is IGNORED; lens-scoped from the JWT only. NO vector index in v1 (over `readEvents` directly).
- **D-d — KPIs = server read-model query fns; honesty guardrail.** Each KPI returns `{value | UNKNOWN, backing: {kinds, filter}}` so the UI deep-links to `GET /v1/events`. Honestly computable now: **unbilled** (pod-without-invoice anti-join), **OTD** (`pod.signed.ts <= legs.appt_window_end_ts` on the delivery leg), **dwell** (`departed.ts − arrived.ts` pairwise), **lane P&L** (money_lines joined shipment→legs→facilities for the lane key). **DSO** needs a minimal AR-settlement projection (populate `invoices.due_ts`/`terms` at issue + a `payment.received → invoices.status='paid'` transition) — build it (also serves WP-11 Collector). **OR** (Operating Ratio) has NO true operating-cost kind — compute an honest, clearly-labeled contribution/margin ratio from `money_lines` (AR) vs the rater cost basis on `quote.priced`, drillable to those events; if that basis is absent, the tile reads `UNKNOWN`. NEVER a fabricated OR/DSO.
- **D-e — Queues (REQ-082): approvals (durable projection + action), exceptions (durable read-model), money = unbilled + aging.** A new `kind`-filtered `readEvents` supports "list open items." Held-invoice visibility stays WP-11 (the Biller's own deferral); the WP-10 money queue is unbilled + open AR aging.
- **D-f — Fix the finance-role `approval.decided` block.** `events.ts:172-174` blocks finance from any non-privileged kind, but a DUAL approval requires finance. Add `approval.decided` to the privileged-decision handling (or a dedicated approval route with `required_role` enforcement) so finance can record a dual approval, + the approvals projection (open on `approval.requested`, decided on `approval.decided`).
- **D-g — Design CI goes BLOCKING at WP-10 exit (REQ-158).** Every new command view must be token-only (5 colors, 2 fonts, no shadow/gradient/radius>4px), reuse Metric/CountUp/Reveal (never hand-roll motion; any `@keyframes` needs its own reduced-motion guard). Flip `design-ci.json` advisory→blocking as the final exit chore.
